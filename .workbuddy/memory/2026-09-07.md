### 编译阶段踩坑 → 解决

**问题**：执行 `bash run_mvn.sh`（mvn package -o -DskipTests）失败，错误：
> Cannot access maven2-plugin/central in offline mode and the artifact org.slf4j:slf4j-api:jar:1.7.36 has not been downloaded from it before.
> 同类还有 com.google.code.findbugs:jsr305:jar:3.0.2

**根因**：Maven 3.9 resolver 默认 strict 校验：本地 jar 的 `_remote.repositories` 文件记录着该 artifact 是从哪个仓库 ID 下载的（这里是 `clife-maven-releases`），offline 模式下必须确认该仓库 ID 在当前 build context（settings.xml active profile）里登记。settings.xml 中 `clife-maven-releases` 已在 active profile 的 repositories 中，但 **plugin 的 transitive 依赖走 pluginRepositories 之外的解析路径**，导致 plugin 依赖的 transitive 校验失败。代码本身编译成功（`Building jar` 已生成），最终失败在 `spring-boot:repackage` 阶段。

**解决**：Maven 3.9 引入 `-Dmaven.legacyLocalRepo=true`（**Maven Resolver 内部属性**），回退到 Maven 3.8.x 的宽松校验行为，不严格比对 `_remote.repositories` 来源记录。把它加进 `run_mvn.sh` 的 JVM 参数（launcher classworlds 级，不是 maven plugin 参数）后：

```
java -classpath .../plexus-classworlds-2.11.0.jar \
  -Dmaven.home=... -Dmaven.multiModuleProjectDirectory=... \
  -Dclassworlds.conf=.../bin/m2.conf \
  -Dmaven.legacyLocalRepo=true \          # ← 关键
  org.codehaus.plexus.classworlds.launcher.Launcher \
  -o package -DskipTests
```

**结果**：`mvn package -o -DskipTests` BUILD SUCCESS（19s）。jar 内含全部新类：
`VisionService.class / VisionController.class / VisionProperties.class / ChatAttachment.class`。

注意：之前曾尝试批量删除 3489 个 `_remote.repositories` 文件（用 `find -delete` 与 `xargs`），但 find 遍历全仓库 14 分钟超时被杀，最终删了约一半就放弃了。`legacyLocalRepo=true` 是更干净、零副作用的方案——**应作为后续 My_Agent 离线打包的默认 flag**，而不是继续清 `_remote.repositories`。

### 关键设计取舍

- **图片不进数据库/不进 RAG**：caption 仅当轮注入，刷新/重开会话不再出现 → 保持对话存储轻量，也避免 RAG 索引膨胀；
- **主对话模型不变**：复用 qwen3.7-plus，识别另起 qwen-vl-plus，避免引入 vision 兼容风险；
- **Controller 层拼接 message**：ChatService / ChatComposer / RoundHandler 全链路零改动，附件概念只留在 Controller，边界清晰；
- **chat/stream 已支持 attachments 透传**：未来加视频/音频只需新增 ChatAttachment.type 与 VisionService 分支，协议层已稳定。
