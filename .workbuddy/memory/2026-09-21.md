## 有界工具循环（工具组合调用）

给 Spring AI 2.0 默认的「无限工具循环」装上刹车，`mvn package` BUILD SUCCESS。

### 关键结论（踩坑后确认的框架机制）
- Spring AI 2.0 的工具调用**天生就是循环的**：`ToolCallingAdvisor.adviseCall` 里 `do...while(isToolCall)`，模型返回 toolCall 就执行工具、把结果拼回 instructions 再调模型，直到不再返回 toolCall。「查表→查数→画图」这类有依赖的多步链本来就支持，无需自己写循环。
- 该循环**默认无迭代上限**，只靠模型自己停止，模型反复调同一工具会死循环。所以「工具组合调用」要做的不是实现循环，而是**给循环装刹车**。
- `ToolCallingAdvisor` 的 bean 来自 `ChatClientAutoConfiguration.toolCallingAdvisorBuilder`（`@ConditionalOnMissingBean`，返回 `ToolCallingAdvisor.Builder<?>`）。覆盖方式 = 提供一个**同类型** `ToolCallingAdvisor.Builder<?>` bean。
- `ToolCallingAdvisor` 提供 `doBeforeCall`（每轮模型调用前触发，返回处理后的 request）与 `doFinalizeLoop`（循环结束触发）两个 protected 钩子，可 override。
- `Prompt.augmentSystemMessage(Function)` 可给 system 追加指令（软刹车用）。

### 新增/修改
- 新增 `properties/ToolCallProperties.java`（`agent.tool-call.*`：max-iterations=10、repeat-threshold=3，compact constructor 兜底）
- 新增 `advisor/BoundedToolCallingAdvisor.java`：继承 ToolCallingAdvisor，ThreadLocal 计数，重写 doBeforeCall 做「轮数上限 + 连续重复检测 + 软刹车（augmentSystemMessage 追加停止指令）」，braked 标记防重复追加，doFinalizeLoop 清 ThreadLocal
- 新增 `config/ToolCallingConfig.java`：提供 `ToolCallingAdvisor.Builder<?>` bean 覆盖默认（内嵌 BoundedToolCallingAdvisorBuilder 子类，override build() 返回有界 Advisor）
- 改 `MyAgentApplication.java`：登记 ToolCallProperties
- 改 `application.yaml`：加 `agent.tool-call` 段
- 改 `README.md`：工具调用节补「有界工具循环」

### 遗留边界（已知取舍）
- 软刹车是「请求」模型停止（追加指令），不强制中断循环；模型若不听话仍会继续调工具，最终靠全局 60s 超时兜底。正常模型遵守指令，99% 场景足够。
- 成本看板：用户已提出但本轮未做（聚焦工具组合调用），下一步待做——agent_trace 已有 prompt/completion/total_tokens + elapsed_ms + tool_calls 字段，落点是 CostService 聚合 + GET /api/cost + 前端看板。

1. **「替换全限定名」漏掉 package 声明行**：脚本用 `org.luo.X.ClassName`（带类名）做替换，能改对 import，但 `package org.luo.X;`（只包名没类名）匹配不上。**正解：按「目录路径」直接重写每个文件的 package 声明**（`relpath.replace('/', '.')`），一次对齐，无需逐个映射。

### 截图自查新坑（重要）
- **`--force-prefers-reduced-motion` 是截动画页终态的钥匙**：landing 页 `.rise` 入场动画在 headless 下时序不可靠（8000ms 预算截到半截、25000ms 反而全页半透明——虚拟时间与合成器动画不同步），加这个开关命中 CSS 的 reduced-motion 降级块（`opacity:1; animation:none`），一次截到终态。
- **curl 本地服务必须 `--noproxy '*'`**：系统代理会把 127.0.0.1 的请求吃掉返回 502。
- Bash 工具的 `&` 起后台服务会被回收（且该环境没有 `sleep`），**必须用 run_in_background**。

### 教务系统业务化重构（用户反馈「菜单问题太多」）
- 根因：原设计是**表结构驱动**（10 表 + 4 查询平铺 14 项菜单），不是业务驱动。用户确认三点：菜单太散、分类不合理、缺真正业务功能。
- 重构为 4 个业务分组：总览（数据看板）/ 基础档案（科目/老师/班级/学生/学期）/ 教学安排（课程/排课/班级课表）/ 考试与成绩（考试/成绩录入/成绩明细/成绩统计/考试日程）。
- **外键可读化走「字典接口」而非逐表 join**（路线 B）：后端只加 `GET /api/edu/dict`（一次性返回 7 个字典，courses/exams 由后端拼好「班级·科目·老师·学期」可读 label）+ `GET /api/edu/dashboard`（总量 + 年级分布 + 各科老师分布）。前端拿裸 ID 本地映射名称，表单下拉也复用同一份字典——避免给 7 张表各写 join SQL。
- edu.js 列元数据新增语义：`fk`（表格显示外键名称）、`fkLabel`（courses/exams 拼接串）、`fkOptions`（表单下拉源）、`numeric`（保存时转 Number）。数值判定集中在 saveForm 一处。
- **新增 URL 参数直达视图**：`edu.html?view=table:student` / `query:timetable` / `dashboard`，便于分享定位（也是无后端截图自查的抓手）。
- 踩坑：`nameMap` 若用 `List<?>` + `Function<Object,Integer>` 收方法引用（`Clazz::getId`）会编译错（方法引用需要 `Function<Clazz,...>`）→ 改成泛型 `<T> Map<Integer,String> nameMap(List<T>, Function<T,Integer>, Function<T,String>)`。
- 无后端环境下看板区空白是预期（`v-if="dash"`），真实验证需用户启动后端。

### 下拉框闪一帧修复（复现了 AI 页的老坑）
- 用户反馈教务下拉框「闪一下」= 记忆里的老坑：原生 select 弹层由系统绘制，option 自定义色走「先建原生弹层再套色」路径 → 点开闪一帧。上一轮给 edu.css 的 option 写色正是元凶。
- 修复：把 AI 对话页的 **UiSelect 组件**（app.js 183-323 行，Teleport 到 body 的自绘下拉）移植进 edu.js + 复制 .ui-select CSS 到 edu.css（色板变量同名直接可用）；替换 3 处原生 select（关联查询筛选×3、表单外键下拉、分页大小）；删除 option 写色规则。
- **新坑（重要）：in-DOM 模板里自定义组件不能自闭合**。edu.html 是 DOM 内模板，`<ui-select />` 会被浏览器 HTML 解析器当未闭合开标签，后续 v-else 失去相邻 v-if，报 Vue compiler-30（"v-else/v-else-if has no adjacent v-if"）→ 整页挂载失败、boot-tip 不消失。**必须写显式闭合 `<ui-select></ui-select>`**。app.js 里没事是因为那是 `template:` 字符串模板。
- 排查手段沉淀：headless Chrome `--enable-logging=stderr --v=0` 能抓 CONSOLE 报错（含 Vue 生产版错误码）；`--dump-dom | grep -c boot-tip` 判断 Vue 是否挂载成功（0=成功）。

## 教务后端分层重构（两轮：去冗余 → 每表独立 Controller/Service）

用户对 `EduService`/`EduController` 两个巨型类不满，分两轮整改，均 BUILD SUCCESS。

### 第一轮：消除透明转发与不必要封装
- `EduService` 原 334 行，50+ 个单表 CRUD 纯转发方法 + 泛型 helper（doPage/doGet/checkUpdate/nameMap/join）全删；`getSubject` 里那行孤立无意义的 `subjectMapper.selectById(id);` 也删。
- 单表 CRUD 改由 Controller 直接调 MyBatis-Plus 通用方法；Service 只留 `dict()`/`dashboard()` 两个跨表组装。

### 第二轮：业务拆分（用户明确「每表 Controller + 每表 Service」）
- 最终结构：10 张表各一对 `{Entity}Controller` + `{Entity}Service`（Service 提供 page/get/save/update/delete 五方法直调 Mapper，含 ensureAffected 0 行抛 404 幂等校验）。
- 跨表能力独立两个类（不破坏前端 endpoint 路径）：
  - `EduMetaService` + `EduMetaController`：`/api/edu/dict`、`/api/edu/dashboard`（外键拼接 + 看板统计）。
  - `EduQueryService` + `EduQueryController`：`/api/edu/score-detail`、`/score-stats`、`/timetable`、`/schedule`（4 个关联查询，SQL 在 Mapper XML）。
- 删除旧 `EduController`/`EduService`，已确认 target 无残留 .class。

### 关键约束（务必复看）
- **REST 端点路径不能变**：前端 `edu.js` 用 `meta.endpoint` 动态拼 `/api/edu/{endpoint}`，且关联查询 endpoint 是 `score-detail`/`score-stats` 这种带连字符的顶层路径（非 `/scores/detail` 嵌套）。所以关联查询不能塞进单表 Controller 的 `@RequestMapping("/api/edu/scores")` 下（会变路径），必须独立 Controller 挂 `/api/edu`。**拆 Controller 时先对前端 endpoint 清单，别顺手改成嵌套路径。**
- 拆分后 Service 层单表 CRUD 仍是直调 Mapper（用户明确要这层，即便有转发），业务逻辑（dict/dashboard 组装）归 EduMetaService。
- 批量生成 10 对文件用 Python 脚本（`gen_edu_split.py`，项目根，用后已删）；脚本写 `/tmp` 会因 Git Bash 路径映射失败，须写项目内。

## 教务后端收敛到路线B（官方 IService/ServiceImpl + 统一返回）

用户定「只改 edu 的，按路线B」——不自拷贝 MP 基类，直接用官方 `IService`/`ServiceImpl`，并统一返回体。`mvn package` BUILD SUCCESS，已核对 target class 为新产物、旧类无残留、edu.js 语法 OK。

### 修的两处编译断点（上一轮删基类留下的中间态）
- `common/service/BaseService{Impl}` 已删，但 `TeacherService extends BaseService<Teacher>` / `TeacherServiceImpl extends BaseServiceImpl` 还挂着。
- `GlobalExceptionHandler` 仍 import 已删的 `org.luo.ai.dto.ErrorResponse`。

### 改动
- `TeacherService` → `extends IService<Teacher>`；`TeacherServiceImpl` → `extends ServiceImpl<TeacherMapper,Teacher>`；`page(dto)` 真实下传 dto（原传 null → 筛选永远失效）；删掉重复的 get/save/update/delete 与双重 Mapper 注入（`@Resource` + 基类 `baseMapper`）。
- `TeacherMapper.getTeacherPage` 返回 `List` → `IPage<TeacherVO>`（与 `ScoreMapper.selectScoreDetail` 写法对齐，分页插件回填 total）。
- `TeacherController` → `GET` 分页（前端本来就是 `GET /api/edu/teachers?page=&size=`，旧 `POST /page` 是 405 契约 bug）+ `RestResult<PageResult<TeacherVO>>` + `require()` 404 + update 补 `setId`。
- `EduMetaController`(dict/dashboard)、`EduQueryController`(4 关联查询) 接 `RestResult` / `RestResult<PageResult<...>>`。
- `GlobalExceptionHandler` 4 个 handler → `RestResult.fail(code,msg)`（HTTP 状态码不变；属性是超集，AI 页前端读 `code`/`message` 仍兼容）。
- `edu.js` 5 处读取改从 `res.data` 解包（loadPage/loadQuery/loadQueryPage/loadDashboard/loadDict）。

### 契约
`RestResult<T>{code,message,data}`（成功 200/ok）+ `PageResult<T>{records,total,page,size,pages}`（`PageResult.of(IPage)`）；成功与异常两条路径同形状。

### 关键结论
- **不要自拷贝 MP 基类**：官方 `IService`/`ServiceImpl` 本就在 classpath（mybatis-plus-extension），自拷贝会连带 internal API、废弃方法与空实现（`page(pager,t){return null;}`）。要基类就用官方的。
- **改返回体必须同步前端解包**：所有 `await r.json()` 的读取点都要取 `.data`。
