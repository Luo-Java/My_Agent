## 天气链路修复（多轮上下文）
- 问题：普通对话「今天天气→深圳→上海呢」，第三轮「上海呢」被追问补全日期。根因：天气是**工具**（非 paramSchema 智能体），模型在多轮工具调用里不继承上一轮 date，缺参反向追问。
- 方案 A（用户选定）：`WeatherTools.queryWeatherByDate/queryWeatherByRange` 的 date/startDate/endDate 改 `required=false`，`doQuery` 缺省回填今天；city 保持必填。
- 已知边界（用户接受）：「明天深圳→上海呢」会落到今天而非明天，不引入跨轮日期记忆。
- 用户后续在管理界面把「天气智能体」的 paramSchema 日期参数也改成非必填——代码侧 `ParamFillingService.missingRequired` 天然支持（只统计 required=true），无需改代码。链路自洽：不追问 → 模型带 city 调工具、date 空 → 工具回填今天。

## C 方案（跨轮任务状态持久化）设计定案（2026-09-21 补充）
- 设计文档 `docs/跨轮任务状态持久化-设计方案.md` 已定案，四个关键决策：
  1. 续跑走**显式按钮** `POST /api/chat/task/resume`（按 conversationId 定位，不自动接续）。
  2. **单会话单 RUNNING** 任务；开新规划时自动把旧 RUNNING 标 CANCELLED。
  3. 任务 DONE 时写「目标→result」进 chat_message（复用 savePlannerExchange），RUNNING 中断不写。
  4. 失败步骤不建 UI，progress 播报「步骤 X 失败已跳过」。
- 数据模型：`task`（id/conversation_id/user_goal/status/total_steps/done_steps/result）+ `task_step`（step_index/agent_code/instruction/depends_on/status/output/citations/**retry_count**）。
- 失败步骤处理（已定案）：FAILED 步骤续跑时重试一次，累计失败 ≥2 次则跳过（视为前驱失败）；SKIPPED（agent 不存在）不重试。靠「重试一次退避」代替异常分类，避免确定性失败反复白重试。
- 状态机：任务 RUNNING→DONE/FAILED/CANCELLED；步骤 PENDING→RUNNING→DONE/SKIPPED/FAILED。
- 改动清单：新增 Task/TaskStep 实体、TaskMapper/TaskStepMapper、TaskService、TaskController（resume 端点）；改 PlannerRoundHandler（结旧开新+步骤落库）、ChatService、schema.sql/alter.sql、README、前端 chat.html/js（继续执行提示条）。
