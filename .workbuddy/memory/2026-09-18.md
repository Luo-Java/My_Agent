**踩的坑（都是实测才发现，靠猜会走偏）**：

1. **`-webkit-line-clamp: 2` 在 flex 卡片里会整段不渲染**：卡片若没有 `.agent-card-code` 那一行（智能体未设 agent_code），描述 `display:-webkit-box` + `min-height:39px` 直接**一个字都不显示**（不是截断，是全空）。同页有 code 的卡片却正常，所以不是全局样式问题。改成 `display:block` + `min-height/max-height: 39px` 后正常。
2. **无头截图会复用旧 CSS，且现象极具迷惑性**：改了 `style.css` 后连续 4 次截图**字节数完全相同（216138）**，看着像「改了没生效」，实际是 Chrome 读了缓存样式表 —— 换 `--user-data-dir`、加 `--disable-http-cache` 都没用。定位靠 **CDP 探针**（读 computed style + rect）证明代码侧已生效，从而把问题锁回渲染缓存。稳妥做法：**每次给 `<link>` 的 href 加 `?t=xxx`**，或直接用 CDP 读值而不是截图。
3. **HTML 区间切片不要用裸子串定位闭合标签**：用 `t.index('        </div>')` 找 grid 闭合，命中了卡片内部 16 空格缩进的 `</div>`（子串匹配不看行首），生成的空态页结构错乱。改为 `re.search(r"^        </div>$", t[i:], re.M)`（锚定行首缩进）后正常。

## 五、输入区开关改版（智能规划 / RAG）

用户：「对话框下面的智能规划开关，rag开关太丑了」。

**先复刻真页面截图确认「丑在哪」，不靠猜**（真 `style.css` + 真 DOM + 5 种状态：都关 / 各开 / 都开 / 禁用）：

1. 开启态是**整块高饱和实底**（`--primary` / `#10b981`）+ 白字加粗 + `box-shadow: 0 2px 14px` 外发光 —— 两个并排时亮蓝撞亮绿，视觉权重盖过右侧「发送」主按钮（开关是状态，被画成了主操作）。
2. `.planner-toggle` 与 `.rag-toggle` 是**两份复制粘贴的样式**，除了颜色完全一样。
3. emoji（🧭📚📎）全彩渲染，色彩与 UI 色板无关，一行里显得杂。
4. 三件尺寸不齐：附件 `padding:5px 12px`/13px，开关 `padding:4px 12px 4px 10px`/14px。
5. 999px 胶囊 + 1.5px 边框，三个并列像三个按钮。

**改法**：

- `style.css` 整段重写（原 709-845 行 → 130 行）：`.planner-toggle, .rag-toggle` **共用一套几何与交互规则**，色相由 `--tg-rgb`（底色）/ `--tg-fg`（文字色）两个变量区分：蓝=规划、绿=检索。
- 关闭态：无底无框、文字 `--text-soft`；hover 才上 10% 淡底并着色调。
- 开启态：淡色底 14% + `inset 0 0 0 1px` 内描边 38% + 着色文字加粗，**取消外发光与白字**。
- 三件套统一 `height: 28px` / 圆角 8px / 字号 13px（附件按钮保留 1px 细边，维持「它是动作、开关是状态」的区分）。
- `chat.html`：emoji → `currentColor` 描边的线性 SVG（回形针 / 两入一出节点汇聚 / 堆叠库），随所在控件文字色一起亮起。

**图标调了 4 轮才定**：14px 的 route / book-open 在截图里糊成小方块和圆点 → 提到 15px + `stroke-width: 1.7` → route 换成线条更少的「节点汇聚」，book-open 换成闭合书本（仍像方框）→ 最终换成**堆叠库**（椭圆 + 两弧，线条最少，语义指向检索库）。
