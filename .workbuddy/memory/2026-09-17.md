**装的时候踩的四个坑（都真踩了）**：
1. 系统 node `D:\software\node\node.exe`（v24.19.0），npm 的 `prefix`/`cache` 指向 `D:\software\node\node_global|node_cache`，而 **`node_cache` 不可写（EPERM mkdir `_cacache`）** → 安装必须 `--cache <可写目录>`。

3. **`package.json` 里没写 `dependencies` 时跑无参 `npm install`，npm 会把 node_modules 当成多余的清空**。我第一次安装中途失败留下半成品（缺 `@modelcontextprotocol/sdk`），第二次无参 install 直接把 sdk 删掉、报 `ERR_MODULE_NOT_FOUND`。→ 必须先把依赖写死进 `package.json` 再装。

## 十、聊天页「一进来就是链路追踪、还关不掉」→ 前端依赖本地化

用户报「首页点进控制台，显示的是链路追踪，还关不掉」。**这是上一步让他 Ctrl+F5 强刷引出来的**（此前浏览器一直命中 CDN 缓存，掩盖了缺陷）。

**修复三层**：

3. **失败提示**：`<body>` 加静态 `#boot-tip`（**内联样式**，style.css 没加载也可见），挂载成功后由 app.js 移除；`app.js` 顶部加 Vue 缺失守卫，把 `ReferenceError` 换成可读的 console 错误。

1. **`--dump-dom` 输出 0 字节会造成假阴性**：两次 grep 都是「0 个 modal-mask」，一度以为没复现，实际是输出文件为空（空文件 grep 当然无匹配）。**grep 前先 `wc -c` 确认文件非空**；dump-dom 在新 profile / Chrome 实例复用时可能静默不输出，而截图命令一直正常 → 排查优先用截图。

## 十三、从首页进入控制台不再自动打开历史会话

**问题**：`chat.html` 的 `onMounted → loadConversations()` 在列表非空时会 `selectConversation(list[0].id)`，于是从首页点进来就自动翻出最近一条历史会话。用户要求「从首页进来不要打开会话历史」。

- `app.js`：`loadConversations(autoSelect = true)`，`autoSelect=false` 时只把列表填进侧边栏就 `return`（**list 为空也不新建会话**）；`onMounted` 读 `fresh=1` 后**立刻 `history.replaceState` 抹掉参数**（否则用户在本页 F5 又回到空白页），再 `loadConversations(!fresh)`。

**保持不变**：侧边栏历史列表照常显示（只是不自动选中）；刷新页面 → URL 已无 `fresh`，回到「自动打开最近会话」的原行为（即刚聊的那条，排最前）。

**验证**：`node --check` app.js / landing.js 通过；离线 `mvn package` EXIT=0；zipfile 核对 jar 内 `index.html` 含 `chat.html?fresh=1`、`app.js` 含 `loadConversations(autoSelect = true)` 与 `loadConversations(!fresh)`。改动 3 个文件：`static/index.html`（+2 行）、`static/js/landing.js`（1 行）、`static/js/app.js`（loadConversations 加参数 + onMounted 读参）。

**待用户在 IDE 自启后确认**：从首页进入落在空白欢迎页；侧边栏点历史会话仍能打开；本页 F5 会恢复最近会话。
