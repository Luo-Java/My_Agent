## PageResult 增加 of(IPage, List) 重载（自定义分页返回 List 形态）

用户手改 Teacher 链为「Mapper 返回 `List`、Service 返回 `PageResult`、手动 `PageResult.of(page, list)`」后编译不过（缺重载），本轮补齐。

### 改动
- `PageResult.of(IPage<T>)` 改为委托 `of(p, p.getRecords())`；**新增 `of(IPage<T>, List<T>)`**。
- `TeacherController` 去掉多包的一层 `PageResult.of(...)`（Service 现直接返回 `PageResult`）。
- 清理 3 处失效 `import IPage`（TeacherMapper / TeacherService / TeacherServiceImpl）。
- `mvn package` BUILD SUCCESS；`javap` 核对：`of` 两个重载、`page` 返回 `PageResult<TeacherVO>`、`getTeacherPage` 返回 `List<TeacherVO>`。

### 关键结论（MP 自定义分页）
- Mapper「参数带 `IPage`、返回 `List`」是 MP 官方支持的自定义分页写法：分页插件仍查 count 并把 `total`/`pages` 写回**入参 IPage**，但**不回填 records**（返回 List 时 `page.getRecords()` 为 null）→ 必须用 `of(page, list)` 显式传列表。
- 返回 `IPage` 时（如 `ScoreMapper.selectScoreDetail`）records 由框架回填，用单参 `of(ipage)` 即可。

## 表格列宽回归：`th{width:1%}` 让数据全挤到左边（用户反馈）

上一轮为解决「性别列被摊到 200+px」加的 `.edu-table thead th{width:1%}` + `th:last-child{width:auto}`（意图：多余空间全给操作列）**矫枉过正**：auto layout 下非末列被压到 min-content、操作列变成一张巨大空白列，10 列数据全挤在卡片左侧，右侧一大片空。

### 改法
- 删掉 `th{width:1%}` / `th:last-child{width:auto}` 两条（注释保留，写明为什么不要这么写）。
