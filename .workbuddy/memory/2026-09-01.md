## 提示词模板改用 Spring AI 官方 PromptTemplate/StTemplateRenderer（用户："springai 有 prompt 模板和格式化的类"）
- 需求：把上一轮手写的 `.replace("{xx}", v)` 换成 Spring AI 官方模板引擎。
- 关键调研结论（源码 + ST4 实验实证）：
  - Spring AI 2.0.0 里模板能力已从 core 拆出：`PromptTemplate` 在 `spring-ai-model`（`org.springframework.ai.chat.prompt`），渲染器 `StTemplateRenderer` 在独立模块 `spring-ai-template-st`（`org.springframework.ai.template.st`），底层是 ANTLR ST4（`org.antlr:ST4:4.3.4`）。
  - 占位符语法 `{name}` 与 ST 默认分隔符天然一致。
  - **ST 的坑**：字面 JSON `{"route":true}` 会被 ST 当表达式解析并抛异常（`'true' came as a complete surprise`）；必须写成 `\{ \}` 转义才能输出字面花括号。中文尖括号 `<...>` 在 `{ }` 分隔符下安全。
  - **依赖坑**：`spring-ai-template-st` 的 pom 错误地声明了 `antlr4-runtime:4.13.1`，而 ST4 4.3.4 实际运行时依赖 `org.antlr.runtime`（antlr-runtime 3.x）包，antlr4-runtime 里没有该包 → 只引 starter 会 `NoClassDefFoundError: org.antlr.runtime.CharStream`。故 pom 需显式补 `org.antlr:antlr-runtime:3.5.3`。
- 落地：
  - pom 引入 `spring-ai-template-st`（模块本体，starter 未在离线仓库）+ 显式补 `antlr-runtime:3.5.3`。
  - `PromptProperties` 加静态 `render(String template, Map<String,?>)` 方法，内部 `StTemplateRenderer.builder().validationMode(ValidationMode.NONE).build()` 的 `apply(template, vars)`。
  - prompts.yaml 把 4 处字面 JSON 花括号转义为 `\{ \}`（router-system 三处、router-continuation-hint 一处、planner-system 一处含内层）。
  - 3 个服务类改 `PromptProperties.render(...)` + `Map.of(...)`：AgentRouter（continuationHint/contextBlock/agentList 三个占位）、ParamFillingService（schemaText）、PlannerService（agentList）。顺手清了 AgentRouter 里未使用的 `PromptTemplate` import。
- 端到端验证：用项目真实 classpath（dependency:build-classpath）跑 `StTemplateRenderer` 渲染真实模板，占位符替换、转义 JSON 输出、中文尖括号保留全部正确。
- 编译 MVN_EXIT=0。生效：重启服务。以后在 yaml 提示词里写 JSON 示例记得写 `\{ \}`。
